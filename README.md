# MCHOSE G3 V1 WebHID

在 Windows 上为迈从 G3 V1 开发本地网页配置工具。**v0.9.1 已支持 USB 有线与 2.4G 接收器的配置读写。** 支持125/250/500/1000Hz回报率、自动连接与唤醒恢复、2–6个DPI档位、多套灵敏度预设和JSON备份。通用按键测试无须官方驱动或WebHID授权。橙色主题、默认深色；蓝牙配置、消抖、按键重映射及宏尚未适配。

## 启动

需要本机 Node.js 20 或更高版本和桌面版 Chrome。没有 npm 依赖，无须安装包。

```powershell
cd D:\MCHOSE_WebHID
npm start
```

通过 `http://127.0.0.1:8787` 打开页面；不要直接双击 HTML。服务仅监听本机回环地址，停止命令为 Ctrl+C。换端口会改变浏览器授权所属的网站地址。

侧边栏“设备设置”（`/#settings`）上方为设备连接/电量与回报率两张卡片，下方集中编辑 DPI 和灵敏度预设；窄屏自动上下排列。鼠标线稿右侧保留竖向电量条。“按键测试”（`/#test`）提供通用五键、滚轮和连击提示。“调试”（`/#debug`）包含通信记录、配置快照、设备描述及诊断导出。三页切换保持当前连接、编辑内容和测试计数。首次打开为深色，侧边栏底部可切换深浅模式并记住选择。

连接USB有线鼠标或2.4G接收器。点击“连接鼠标”，在浏览器弹窗中选择有线`G3 Gaming Mouse`（258A:0136）或接收器`Wireless Mouse`（258A:0138）。手动连接总是打开选择框，便于切换设备；已有唯一匹配授权时，页面启动会自动复用并读取配置，不弹选择框。多份可用授权不会自动猜测目标。本机实测拔插后可能需要再次选择，不能保证重插后授权仍在。页面按实际设备显示“USB有线连接”或“2.4G无线接收器”。

退出官方 HUB，轻动鼠标保持唤醒。页面先核对 G3 产品标识，再读取并校验配置；也可手动点击“读取设备配置”。硬件代际 V1 由用户提供，不仅凭 VID/PID 推定。

鼠标报告离线时清空电量与配置，收到上线通知后自动恢复配置；缺少配置时的有效电量/档位报告也可触发恢复。自动请求合并执行，与手动读取、DPI和回报率保存共用串行锁。瞬态读取失败最多尝试3次，并保留重试间隔；型号或数据校验异常停止自动读取，保留手动读取入口。不会自动重复配置写入。

2.4G电量由接收器通过Input Report被动上报；自动恢复主动查询的只有产品标识和配置。有线模式本轮没有观察到电量上报，显示“--”，不据此推断电量或充电状态。

点击“断开连接”后，本页暂停自动重连；手动再次连接可恢复，刷新页面会重新启用。接收器重插或页面重新获得焦点时可检查已有授权。授权与连接规则参考 [Chrome WebHID 文档](https://developer.chrome.com/docs/capabilities/hid)。

在“回报率”卡片中选择 **125、250、500 或 1000 Hz**，点击“应用回报率”写入。卡片上方显示设备已读回的当前值，选中另一档只改变草稿。各档理论上报间隔分别为8、4、2、1ms。回报率独立于灵敏度预设，保存时仅修改回报率及校验值，保留设备当前DPI、当前档位及其他字段。切换预设、读取和唤醒恢复保留待应用的回报率；未应用的DPI草稿不会随回报率保存写入设备。

读取后，在“DPI 档位”中编辑数值，用“添加档位”和每行“删除”调整数量。范围为 **2–6 档、100–12000 DPI、步进 100**，当前同步修改 X/Y。圆点选择应用后的当前档位；删除当前档位时自动选定有效档位。编辑完成后点击“应用 DPI”。设备当前已经是这套值时，应用按钮禁用。

“新建预设”可从两档开始编辑；填写名称后点“保存预设”。选择已有预设可载入、改名和保存，也可“另存为新预设”或删除。**保存预设存入当前浏览器；应用到鼠标才修改设备。** 预设记住各档数值和当前档位，回报率等其他设置沿用设备当前值。网页预设独立于官方 HUB 的 INI 文件，不自动同步；页面刷新后预设仍在，清除本站数据会删除预设，请用“导出预设”备份。导入接受本工具的预设 JSON，保留已有预设；同标识不同内容会另存一份。

另存、导入、导出和删除位于预设栏的“更多操作”中。有线与2.4G使用相同的DPI和回报率编辑入口；两者都先验证接口、报告长度和G3产品码，再允许配置读写。

切换预设或从设备重新载入时，未保存编辑会暂存在当前页面，可点“恢复上个草稿”（最多10份）；刷新或关闭页面会清除这些临时草稿。多个标签页通过浏览器存储锁合并预设更新；同一预设发生外部修改时会拒绝直接覆盖，可重新载入或另存。

v0.5.1：鼠标DPI键切换后，当编辑区与设备为同一组DPI数值时，下方圆点和行高亮会自动跟随当前档位，无须点击应用。网页手动选定的待应用档位不会被每秒刷新覆盖；数值/数量不同的未应用预设保留自己的选择。此同步只更新界面，不自动写入鼠标或保存预设。

v0.6.0 自动恢复也保留尚未应用的档位选择。只有真实的DPI档位通知会覆盖该选择并跟随鼠标；单纯重新读取配置不会覆盖待应用目标。“从设备载入”可显式重置为设备当前状态。

每次应用都会重新核对型号并读取硬件新基线。DPI保存只修改数量、当前档位和有效档位X/Y；回报率保存只修改回报率。两者均保留其他字段及未启用槽，读回整个408字节一致才显示核对成功。失败时不自动重复写入；若提示未确认，先重新读取。保存期间保持鼠标唤醒、不要按 DPI 键。最多10次写入前后的原始包保存在当前页面会话，可通过诊断导出；刷新前请导出需要保留的历史。

有线保存后的首次GET若出现`NotAllowedError`或`NetworkError`，会在该请求结束后等待500ms，再做一次只读复核。期间保持串行锁，配置写入只发一次；任意DPI通知、离线或连接变化都会阻止确认。第二次仍失败，或返回数据校验失败、与预期不一致时，保留“未确认”，请先读取设备。这个处理覆盖了本轮真实出现的GET失败，但没有确定其底层原因。

v0.4.0 实测 2→6→3→2、100/12000 边界、当前第2/3档及预设应用。五次写入均完整读回匹配，随后把抓包期间改动的未启用槽一并恢复，最终完整配置与当轮初始基线一致：1600/2400、当前第2档、1000Hz。v0.3.0 另有鼠标OFF约5秒重开后仍保留DPI的证据；v0.5.0 本轮为界面重构，只进行了配置查询和浏览器操作，没有重复硬件写入或断电试验。

既有样本电量上报间隔约 48 秒；休眠时不保证继续上报。没有数据不会显示为 0%，超过 180 秒标记为过期。接收器拔出或鼠标明确报告离线时清空当前电量与配置。明确离线时禁用查询；初次连接尚未收到连接状态时，也应先轻动鼠标。

若打开失败，先退出官方 HUB 和 `D:\MCHOSE_Battery` 电量托盘后重试。不需要替换 HID 驱动。网页关闭后停止监听，不能代替后台托盘持续显示。

“导出诊断 JSON”保存浏览器环境、描述符、产品标识、原始配置及最多 300 条事件；通信表显示最近 30 条输入/Feature 记录，长报告显示前缀，完整字节保留在导出文件。不包含设备序列号、Windows 设备路径或其他集合的输入。所有资源在本地，不依赖第三方脚本或云服务。运行网页不需要 USBPcap。

## 按键测试

直接打开`http://127.0.0.1:8787/#test`，把指针移入中间鼠标线稿所在的测试区。支持左键、右键、中键、前进/后退侧键以及四向滚轮事件，按下时计数并高亮；长按不重复，支持多键同时按下。区域外开始的按下不计入，区域内开始后在外面松开仍会清理高亮。测试区内拦截右键菜单、中键自动滚动及侧键导航；区域外保留普通操作。

此页通过浏览器标准输入事件工作，不调用WebHID或官方软件；有线、2.4G、蓝牙和其他品牌鼠标都可测试浏览器能收到的标准按键。无需先连接设备，不支持WebHID的浏览器也可使用测试页。计数反映系统映射后的输入，无法区分同一电脑上多只鼠标的来源；DPI等内部按键及被系统/驱动拦截的功能无法通用检测。触摸和笔输入不冒充鼠标按键。

“疑似连击”统计同一按键相邻两次按下间隔不大于40ms的情况，仅作短间隔提示，不据此判断硬件故障或消抖参数。滚轮按浏览器事件计数，不等同于物理刻度。右侧保留最近60条按下、松开、滚动和中断记录，时间为相对首条记录的秒数。切页保留计数；窗口失焦、页面隐藏或离开测试页时清理按下状态及连击计时。“重置测试”清空全部计数和记录，刷新页面也会清空。

布局参考[迈从鼠标测试页](https://www.mchose.com.cn/#/test-mouse)，图形沿用本项目橙色线稿。组合键事件处理参考[W3C Pointer Events](https://w3c.github.io/pointerevents/#chorded-button-interactions)。

## 文件

- `dist/`：可独立静态托管的 HTML、CSS 和 JavaScript。
- `dist/protocol.js`：设备档案、描述符校验、输入报告解析。
- `dist/identity.js`：已验证产品识别请求与响应。
- `dist/config.js`：已验证基础配置读取与解析。
- `dist/write-dpi.js`：仅针对已验证 G3 基线的单项/档位组 DPI 写包构造。
- `dist/write-config.js`：公共配置包校验、写入头/校验构造和受限Feature发送。
- `dist/write-polling.js`：四档回报率写包构造，与官方抓包逐字节核对。
- `dist/polling-editor.js`：回报率草稿、独立应用及当前值显示。
- `dist/presets.js`：DPI组校验、预设JSON、浏览器持久化和跨标签锁。
- `dist/dpi-editor.js`：档位草稿、增减/选择当前档位与预设界面。
- `dist/session.js`：WebHID 会话、串行查询、断线及异步生命周期。
- `dist/mouse-test-state.js`：通用按键计数、组合按下状态、短间隔提示和有界记录。
- `dist/mouse-tester.js`：测试区标准浏览器事件、线稿高亮、滚轮和记录界面，不依赖HID会话。
- `tools/serve.mjs`：仅提供页面的本地 HTTP 服务，不访问鼠标。
- `tools/capture.mjs`：开发抓包包装器，需真实终端和 Windows UAC，限定指定 USB 地址，默认 180 秒自动结束。
- `tools/pcap.mjs`：离线 pcap 解码、设备身份与控制事务核验，不访问硬件。
- `tools/probe-wired-feature-length.py`：开发用只读长度对照实验，依赖本机既有hidapi，仅查询有线G3的型号和配置，不供网页运行。
- `tests/`：协议与会话测试。
- `docs/PROTOCOL.md`：协议证据与待验证项。
- `docs/PROGRESS.md`：本轮状态和接续步骤。

原电量项目仅作为只读参考，未复制它的后台程序，也不修改其个人配置。

## 开发抓包

先用 USBPcap extcap 查询核实当前 Root Hub/设备地址；地址在拔插后会变化。下面的 `43` 是历史接收器地址；本次有线捕获为地址10，两者都不能直接套用到下一轮。

```powershell
node tools/capture.mjs USBPcap1 43 unique-capture-name 480
node tools/pcap.mjs diagnostics/2026-11-08/unique-capture-name.pcap 43 diagnostics/2026-11-08/unique-capture-name.decoded.json
```

捕获通过 USBPcap 直接写文件。当前终端的 `q` 停止和 stdout 管道方式未成功，采用 Ctrl+C 或有界超时后验证全部进程退出、文件完整记录和控制事务配对；不得把中断后的文件未经校验就称为完整捕获。原始 pcap 只保留本地，不随网页分发。
